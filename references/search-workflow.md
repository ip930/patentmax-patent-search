# 检索工作流

## 找某个主题的专利

```
search 跑两三轮  →  挑出相关的  →  brief 逐篇细看
```

**第一轮先宽。** 用两三个核心词组合，看命中量再决定收窄还是放宽。检索式写法见 [query-syntax.md](query-syntax.md)。

```bash
python scripts/patentmax_client.py search --q "(固态电池 OR 全固态电池) AND 电解质" --size 20
```

`brief`、`similar`、`citation` 都直接接受公开号，拿结果里的 `patent_number` 传过去即可。

**第二轮按结果量调。** 上千条说明太宽，加分类号或时间限定；不足十条先怀疑同义词没扩够，不要急着下「没有相关专利」的结论。

**挑出来的再细看。**

```bash
python scripts/patentmax_client.py brief --patent CN109761224A
```

一次 ¥0.10，著录项、权利要求、说明书全文都在里面。`--fulltext` 把全文也回给模型
（**不额外收费**，只是输出变长）。`--legal` 才是唯一真的另外花钱的开关（+¥0.05），
而判断"还有没有效"看检索结果里的法律状态就够了。

## 吃透一件专利

```
brief（著录 + 权要 + 全文）  →  citation（前后引证）  →  similar（技术近邻）
```

```bash
python scripts/patentmax_client.py brief --patent CN109761224A --fulltext
python scripts/patentmax_client.py citation --patent CN109761224A
python scripts/patentmax_client.py similar --patent CN109761224A --limit 10
```

三条合计 ¥0.25。用户只问"这篇讲了什么"时**只跑第一条**——
后两条回答的是另一个问题，没问就别替他花钱。

看的时候注意：

- **权利要求 1 是保护范围的边界。** 从属权要是在它基础上加限定，范围只会更窄。判断别人的专利拦不拦得住你，先看权要 1。
- **法律状态决定它有没有约束力。** 授权且有效才谈得上侵权；驳回、撤回、届满、无效的专利不构成障碍，但依然是有效的现有技术，做现有技术检索时照样要算进去。
- **引证关系看技术源流。** 它引了谁，说明技术从哪来；被谁引，说明谁在跟进。被引次数常被当作影响力指标，但新专利公开时间短，天然偏低，不能直接横比。

## 找技术方案相近的专利

已经有一件专利，想找技术上最接近的：

```bash
python scripts/patentmax_client.py similar --patent CN109761224A --limit 10
```

这是语义相似，不是关键词匹配——能找到用词完全不同但方案雷同的专利，关键词检索会漏掉这类。

用途：找对比文件、竞品对标、评估自己的方案是不是真的新。

## 摸一个企业的专利家底

先用申请人名检索，再看分布：

```bash
python scripts/patentmax_client.py search --q "申请人:宁德时代" --size 50
```

**注意口径**：申请人名称没有做集团归一化。同一家企业可能以中文名、英文名、子公司名分散在不同记录里，查跨国集团时要分主体查询再合并，否则会严重低估它的专利量。给用户结论时必须说明这一点。

## 结果怎么交付

每次检索完，至少写清楚三件事：

**用了什么检索式、覆盖什么范围。** 用户得能判断这个结果可不可信、要不要补检。把实际跑过的检索式列出来，包括跑了几轮、每轮多少条。

**每条为什么相关。** 一句话说清它和用户的技术方案在哪一点上重合——是解决同一个问题，还是用了同样的手段，还是达到相近的效果。只列标题等于没做筛选。

**结论的边界。** 检索结果只能证明「在这个检索范围内找到了什么」，不能证明「不存在」。尤其要提 18 个月公开窗口期。

建议表格：

| 公开号 | 标题 | 申请人 | 申请日 | 法律状态 | 相关点 |
| --- | --- | --- | --- | --- | --- |

## 省钱

- `search` 一次 ¥0.10 且每天前 30 次免费，多跑几轮不心疼，**但每轮之间要看结果调整检索式**，无脑翻页没意义
- `brief` 一次 ¥0.10 一口价，著录 + 权项 + 全文都在里面，同样算进每日免费额度
- **同一篇专利只调一次 `brief`**，要的东西一次取齐；分两次就是多付一个 ¥0.10
- `--fulltext` **不额外收费**，只是输出很长。不确定要不要读技术细节时就加上，别为此专门再调一次
- 真正另外花钱的只有 `--legal`（+¥0.05），而法律状态在检索结果里已经有了

# 分轮检索

**本节只适用于标准档和完整档。快速摸底就是 5 次检索一把跑完，不分轮、不迭代。**

开始系统检索前，先做 1-2 次试验性检索掌握整体情况，再逐步精确。一次完整的主题检索通常需要 3-5 轮，这是正常的。

**试验性检索也要计数。** 它一样扣 ¥0.10，一样算进预算——实测漏计的大头就是这些"跑完觉得不好就丢掉"的检索。

**试验性检索的目的**：验证关键词在库中有没有命中、评估结果规模、从前排提取真实术语和 IPC、确认申请人名称的完整写法。它的命中结果不直接进候选池，只用于校准后续检索。

**第 1 轮** — 对象 × 机制 × 关键特征跑一式，兼作术语与规模校准；抽查前 10 篇，标出强相关 / 弱相关 / 不相关，识别噪声类型。

**第 2 轮** — 按第 1 轮观察到的噪声收窄、按新术语扩展；加日期或 IPC 限定；必要时分库。

**第 3 轮及以后** — 补充切角、换语言、针对残余缺失特征。**连续两轮不再出现新的关键分类、申请人、特征或引证线索时中止**，跑不满不算失败。

每轮结束后把结果交给用户校准，不要闷头跑完所有轮次：本轮找到几篇强相关（列公开号）、主要噪声是什么类型、发现了哪些新术语或新申请人，然后问他是调整重点、继续当前方向，还是就此收尾。

**每轮同时核对费用**：看输出里的 `_balance`（权威余额）和 `_spent`，和开跑前的预估比。超出预估 1.5 倍就停下来请示（A 追加 / B 收尾 / C 结束），不要自行决定继续。

**这几轮里不要 `brief`。** 试验性检索和分轮收窄靠的是检索结果里的标题、摘要和 IPC 分布——这些检索本身就返回了。单篇精读留到候选池定下来之后，见「先筛后读」。
