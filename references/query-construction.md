# 检索式构造

> 从 SKILL.md 拆出来的详细规则。构造检索式前读这一篇。

## 三块结构（硬规则）

除专利号精确查询、单一申请人盘点外，**不得只用技术对象 + 宽泛功能词执行检索**。技术检索式通常必须包含三个相互独立的 `AND` 块：

1. **技术对象** — 产品、部件、材料或方法场景
2. **核心机制 / 技术问题** — 方案如何工作，或具体解决什么问题
3. **关键区别特征** — 结构关系、步骤关系、控制逻辑、特定部件、参数范围或特殊技术效果中的至少一项

```
(固态电池 OR 全固态电池) AND (硫化物 OR 氧化物 OR 聚合物) AND 电解质
```

信息不足以构造三块时，用两个高置信概念块加上已验证的 IPC 或关系词组，**不要用「系统、装置、方法、设备、处理、控制」这类通用词凑数**。

中文关键词不保证短语匹配，可能按单字切分；引号不能替代结果抽样和详情核对。

优先加入能排除同领域噪声的特征，顺序通常是：关键关系 / 机制 > 特定结构或步骤 > 参数 > 特殊效果 > 通用场景词。

## 执行前自检

| 项目 | 通过标准 |
| --- | --- |
| 独立概念块 | 通常 ≥3；每块表达不同技术维度 |
| 关键特征 | 至少 1 个，不得全部是上位词或通用词 |
| OR 扩展 | 只扩展块内同一概念，不把不同特征用 `OR` 混成一个块 |
| 精确限定 | 至少考虑一个关系短语、下位 IPC、参数、日期或申请人条件 |
| 可解释性 | 能说明新增特征将排除哪类噪声 |

## 命中后的强制动作

| 命中数 | 动作 |
| --- | --- |
| 0 | 多半是 `AND` 串太多或同义词没扩够，**先排查再下结论**，不得直接判定「无现有技术」 |
| 1-20 | 检查是否过窄；保留作高精度块，用其他块补召回 |
| 21-500 | 适合逐篇或分批核对 |
| 501-4,999 | 抽样 5-10 篇；噪声多时增加一个关键区别特征后重检 |
| ≥5,000 | 判定为过宽，**不得直接进入候选池**；必须增加关键特征、已验证 IPC 或日期后重检 |

## 收窄优先级

仍然过宽时，按这个顺序处理，不要机械堆叠低置信词：

1. **加字段限定** — 已验证的下位 IPC、申请日范围、`--scope cn` 缩小库
2. **更换特征组合** — 从前排强相关文献提取真实术语，换一个切角，而不是在原式末尾继续叠加
3. **切换库 / 语言** — 全球库切中文、中国库切英文对应词，不同库前排结果不同
4. **分拆检索** — 按 IPC 或申请人拆成多个窄检索，分批核对

收窄前先看前 5-10 篇的噪声类型，一次性选最有区分力的条件。

## 申请人检索

企业检索优先用**全称**（`宁德时代新能源科技股份有限公司`），简称会带出大量个人申请人噪声。

**申请人名称未做集团归一化**——同一家企业可能以中文名、英文名、子公司名分散在不同记录里，查跨国集团时分主体查询再合并，否则会严重低估其专利量。这一点必须在结论里向用户交代。

## IPC 分类

不熟悉分类号时，先用关键词跑一轮，看返回结果里高频出现哪几个 IPC，再用那几个收窄——比查分类表快，也更贴合实际分类习惯。

不一律截断到四位：先用准确下位组查准，再用上位组补召回。复合检索前先单独预检 IPC；若为 0 条，先修格式或回退上位组，**不得把「错误分类 + 关键词」叠加后的 0 条解释为无现有技术**。
