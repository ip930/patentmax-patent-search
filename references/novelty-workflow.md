# 查新工作流

判断一个技术方案有没有人做过、还能不能申请。

> **这条线花钱。** 一次查新任务约 ¥15，不是 ¥0.10。跑之前必须告诉用户价格并等他明确同意。
>
> 用户只是想「看看有没有类似的」，用 `search` + `similar` 就够了（两次加起来 ¥0.30），不要动查新。

## 什么时候才该走查新

| 用户说 | 走哪条 |
| --- | --- |
| 「有没有类似的专利」「帮我搜一下」 | 检索 + 相似，别用查新 |
| 「这个能不能申请」「有没有新颖性」「帮我做查新」 | 查新 |
| 「要一份查新报告」「立项要交查新材料」 | 查新 + 导出 DOCX |

## 第一步：先把方案问清楚

**技术方案描述的质量直接决定查新结果。** 描述太笼统等于白花 ¥15。

一句「一种新型电池」什么也查不出来。至少要有：

- **解决什么问题** —— 现有技术卡在哪
- **用什么手段** —— 具体的结构、材料、步骤、参数
- **达到什么效果** —— 最好有量化指标

一份够用的描述长这样：

> 采集阀门转轴角度、启闭扭矩及前后水位，根据扭矩增量和积雪含水状态判断卡滞，并控制振动装置清理。

具体到了传感量、判据、执行动作。这种描述才查得出东西。

**用户给的描述不够细，先问，别急着跑。** 问两三个问题的成本远低于跑一次没用的查新。

## 第二步：先用便宜的方式探一下（推荐）

正式查新之前，花 ¥0.30 先摸个底：

```bash
python scripts/patentmax_client.py search --q "阀门 AND 卡滞 AND (扭矩 OR 转矩)" --size 20
```

如果这一步就撞见高度相似的专利，直接告诉用户，可能根本不用跑查新——或者要先改方案再查。

## 第三步：跑查新

```bash
python scripts/patentmax_client.py novelty \
  --title "阀门卡滞诊断与清理装置" \
  --solution "采集阀门转轴角度、启闭扭矩及前后水位，根据扭矩增量和积雪含水状态判断卡滞，并控制振动装置清理" \
  --purpose pre_filing \
  --depth standard \
  --regions global \
  --wait --yes
```

### 参数怎么选

**`--purpose` 查新目的**

| 值 | 什么场景 |
| --- | --- |
| `novelty` | 判断新颖性，最常用 |
| `inventiveness` | 判断创造性，比新颖性更严 |
| `pre_filing` | 申请前查新，要交申请了 |
| `project_screening` | 立项筛查，看方向有没有人占了 |
| `competitor_scan` | 竞品扫描 |

**`--depth` 检索深度**

`quick` 快但浅，`standard` 默认，`deep` 最全但最慢。**申请前查新用 `standard` 或 `deep`**，立项筛查 `quick` 就够。

**`--regions` 地域**

默认 `global`。只关心国内就 `CN`，要覆盖具体几国用逗号分隔：`CN,US,EP,JP`。

**`--patents-only`** 加上这个只查专利，不查论文和网页。**一般别加**——查新的现有技术不限于专利，论文和公开产品资料同样能破坏新颖性。

**`--idempotency-key`** 网络不稳时加一个自定义字符串，防止重试造成重复提交和重复扣费。

### 关于等待

`--wait` 会一直轮询到出结果，退避从 5 秒逐步拉到 30 秒，默认最多等 15 分钟。

**超时不代表失败。** 任务还在服务端跑，千万别重新提交（会再扣一次钱）。用返回的 task_id 继续查：

```bash
python scripts/patentmax_client.py novelty-status --task-id <task_id>
```

## 第四步：读结果

拿到结果不要直接转述，要把这几件事挑出来讲：

**最接近的对比文件是哪几篇。** 按相似度排，重点看前三篇。

**每篇在哪一点上撞上了。** 逐条比技术特征——是解决同一个问题？用了同样的手段？还是效果相近？**看权利要求，不看摘要**：摘要读着像不等于落进保护范围。

**结论怎么下。** 说清楚是「未检索到破坏新颖性的对比文件」还是「存在高度相似的在先专利」，别用模糊表述让用户自己猜。

**边界必须讲。** 三条：

- 专利从申请到公开有约 18 个月窗口期，这期间的申请检索不到
- 检索只能证明范围内找到了什么，不能证明不存在
- 这份结果是技术参考，正式申请前建议由专利代理人复核

## 导出 DOCX

```bash
python scripts/patentmax_client.py novelty-docx --task-id <task_id> --out 查新报告.docx
```

任务必须已经跑完。DOCX 不额外收费，包含在那 ¥15 里。

这份文档可以直接用于立项材料、申请前自查。但**正式的科技查新报告需要有资质的查新机构出具并盖章**，这个要跟用户讲清楚，别让他拿去当官方查新报告用。

## 先免费试跑

把密钥换成 `pm_test_` 开头的测试密钥，查新会立即返回模拟结果，不调用外部服务也不计费。

用来验证参数拼得对不对、结果结构长什么样，确认没问题再换生产密钥跑真的。

## 一次失败的查新长什么样

以下情况别跑，跑了也是浪费：

- 技术方案只有一句话，没有具体手段
- 用户其实想问「这个领域有哪些专利」——那是检索，不是查新
- 用户想查商标、外观设计图像——不在这个 Skill 的范围
- 用户已经跑过一次、只是想换个措辞再试——先看上次结果哪里不满意
