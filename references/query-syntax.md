# 检索式怎么写

`patent_search` 支持 `AND` / `OR` / `NOT` 和括号分组。下面是几条能明显提升召回质量的做法。

## 一、拆成三个面，先取两个

技术主题通常能拆成三部分：**解决什么对象**、**用什么手段**、**达成什么效果**。

三个面全用 `AND` 串起来，往往一条都搜不到——专利文献不会按你的思路组织语言。**先取其中两个跑一轮**，看结果量再决定加不加第三个。

```
(固态电池 OR 全固态电池) AND (硫化物 OR 氧化物 OR 聚合物) AND 电解质
```

这条已经是三面齐全的版本。如果零结果，先砍掉最具体的那一面。

## 二、同义词必须扩

中文专利文献里同一个东西常有好几种叫法，还要考虑英文对应词——在华申请的外国专利译名并不统一，同一个技术可能有三四种译法散落在不同案子里。

```
(无人机 OR 无人飞行器 OR UAV OR "unmanned aerial vehicle")
```

扩词的几个方向：

- **上位词**：锂电池 → 二次电池 → 储能器件
- **下位词**：电解质 → 固态电解质 → 硫化物固态电解质
- **俗称与学名**：光伏板 / 太阳能电池组件
- **英文与缩写**：SEP、PCT、OLED
- **旧称**：很多技术在早期专利里用的是现在没人用的叫法

## 三、按结果量调整

| 结果量 | 说明 | 怎么办 |
| --- | --- | --- |
| 几千条以上 | 检索式太宽 | 加 IPC 分类号限定，或限定申请日范围 |
| 几十到几百 | 比较理想 | 直接看 |
| 不足十条 | **先怀疑同义词没扩够** | 换词再跑，别急着下「没有相关专利」的结论 |
| 零条 | 多半是 `AND` 串太多 | 砍掉最具体的那一面 |

零结果不等于这个技术没人做过。绝大多数零结果是检索式的问题，不是事实。

## 四、`NOT` 慎用

排除词会连带把交叉领域的专利一起排掉。比如查电池想排除「汽车」，结果把车用动力电池的核心专利全排没了。

**宁可多看一些噪声，也别漏掉真正相关的对比文件。** 查新和无效检索尤其如此——漏掉一篇对比文件的代价，远大于多翻十条不相关结果。

## 五、按著录字段查

已知申请人、发明人、公开号、IPC 分类时，直接用字段检索，不要把这些信息拆成语义片段去做模糊匹配——那样只会引入大量噪声。

反过来，只有一段技术方案描述、没有任何结构化线索时，才走关键词与语义扩展的路子。

## 六、IPC 分类号

不熟悉分类号时，先用关键词跑一轮，看返回结果里高频出现哪几个 IPC，再用那几个分类号收窄。这比查分类表快得多，也更贴合实际的分类习惯。

分类号可以只取到大组（如 `H01M10/052`），也可以放宽到小类（如 `H01M`）看整体分布。
