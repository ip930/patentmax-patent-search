## 初衷

> **AI 编专利号这件事，比查不到还糟。**

查不到，你知道要换个地方查。编一个出来，格式对、标题像、申请人是真公司——你信了，拿去写交底书、写立项报告、写技术方案，等到审查员把真正的对比文件甩到面前，才知道前面全是白忙。

问题不在模型笨，在于它手里根本没有专利库。它只能靠训练时读过的零星片段拼一个看起来对的答案出来。

这个 Skill 做的事很简单：**把一个真实的全球专利库接到 AI 手里**。查得到就是查得到，查不到就说查不到，每一条都有公开号可以去官方库核对。

至于为什么定这个价——专利数据这门生意，长期是按年卖席位的，一套系统十几万起，中小企业和个人开发者被挡在门外。我们按次收，检索一次一毛钱。用得起，才谈得上用。

## 能做什么

三块能力：**检索**、**单篇深入**、**统计分析**。

### 检索 · 一次 ¥0.10

```bash
python scripts/patentmax_client.py search --q "(固态电池 OR 全固态电池) AND 电解质" --size 20
python scripts/patentmax_client.py brief --patent CN109761224A
python scripts/patentmax_client.py similar --patent CN109761224A
python scripts/patentmax_client.py citation --patent CN109761224A
```

- **检索** — 关键词或布尔式找专利，支持 `AND` / `OR` / `NOT`
- **速览** — 给一个公开号，**一次 ¥0.10** 返回著录项目、权利要求、说明书全文
- **相似** — 语义相似度找技术方案最接近的专利，能找到用词完全不同但方案雷同的那些
- **引证** — 引了谁、被谁引、引了哪些论文和标准

还支持**字段式检索**：`documentNumber:CN106328959A` 按公开号精确查、`t:区块链` 按标题、`legalStatus:有效专利` 按法律状态、`type:发明授权` 按类型、`applicationYear:[2024 TO 2024]` 按年份范围；六种排序（相关度 / 申请日升降 / 公开日升降 / 综合）和关键词高亮。

### 统计分析 · 一次 ¥0.30

```bash
python scripts/patentmax_client.py stats --q "固态电池" --dimension applicant
python scripts/patentmax_client.py company --name "宁德时代新能源科技股份有限公司"
```

**15 个维度各出 Top 20**：申请人、发明人、申请年份、公开年份、IPC 四级分类、国家地区、省份城市、法律状态、专利类型、外观设计分类。

看一个领域谁在申请、趋势如何、技术怎么分布，换着维度跑几次就清楚——**这通常比逐篇翻专利更接近管理层要的东西**。企业画像则是输入工商全称，看一家企业的专利家底。

数据来自 iprdb 全球专利库，覆盖中国、美国、欧洲、日本、韩国和 WIPO。**中国专利是收录最全的一块**——权利要求、法律事件、摘要附图都有，不是只给个标题就完事。

## 怎么用

**第一步**，到 [api.ip930.com/features/api-platform](https://api.ip930.com/features/api-platform) 注册，创建一个密钥，一分钟的事。

**第二步**，设成环境变量：

```bash
export PATENTMAX_API_KEY="pm_live_你的密钥"
```

完事了。没有配置文件要改，不用重启客户端——**任何能跑 Bash 的 AI 客户端都能用**。

> 同一套数据也提供 **MCP 接入**：端点 `https://api.ip930.com/api/mcp`，Streamable HTTP，支持 OAuth 2.1 一键授权，可直接接进 Claude、Cursor、扣子等兼容 Model Context Protocol 的客户端。这个 Skill 走 HTTP 接口是为了不挑客户端，两条路都通。

`scripts/patentmax_client.py` 只用 Python 标准库，不需要 `pip install`。环境里连 Python 都没有的话，直接 curl 也行，接口清单在 [references/api-reference.md](references/api-reference.md)。

详细步骤和排查见 [INSTALL.md](INSTALL.md)。

## 几条经验

[检索工作流](references/search-workflow.md) 和 [检索式写法](references/query-syntax.md) 里写的不只是接口怎么调，还有几条得踩过才知道的事：

- **检索式要有三块结构** — 技术对象 × 核心机制 × 关键区别特征。只用对象加通用词，命中几千条全是噪声。
- **命中 0 条先别下结论** — 九成是 `AND` 串太多或同义词没扩够，不是真的没有。
- **申请人名称没做集团归一化** — 查跨国集团要分主体查再合并，否则会严重低估它的专利量。
- **检索返回的 id 只活 60 分钟**，详情类接口只认它不认公开号——脚本里处理掉了，自己写 curl 要留神。

## 它不做什么

**不出具有法律效力的意见书。** 可专利性结论、FTO 意见书、无效检索报告都不在本 Skill 范围内——前者走查新任务，后两者需要代理人签字。

**法律状态是快照，不是登记簿。** 涉及侵权、无效、许可这类有法律后果的判断，以各国专利局官方登记簿为准。

**「没搜到」不等于「没有」。** 专利从申请到公开有 18 个月左右的窗口期，这段时间的申请谁也检索不到。

**不做外观设计图像检索、商标检索。**
