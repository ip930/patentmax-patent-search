## 初衷

> **AI 编专利号这件事，比查不到还糟。**

查不到，你知道要换个地方查。编一个出来，格式对、标题像、申请人是真公司——你信了，拿去写交底书、写立项报告、写查新说明，等到审查员把真正的对比文件甩到面前，才知道前面全是白忙。

问题不在模型笨，在于它手里根本没有专利库。它只能靠训练时读过的零星片段拼一个看起来对的答案出来。

这个 Skill 做的事很简单：**把一个真实的全球专利库接到 AI 手里**。查得到就是查得到，查不到就说查不到，每一条都有公开号可以去官方库核对。

至于为什么定这个价——专利数据这门生意，长期是按年卖席位的，一套系统十几万起，中小企业和个人开发者被挡在门外。我们按次收，一次一毛钱，查十次一块钱。用得起，才谈得上用。

## 怎么接上

**第一步**，到 [api.ip930.com/features/api-platform](https://api.ip930.com/features/api-platform) 注册，创建一个密钥，一分钟的事。

**第二步**，把 MCP 配置加到你的客户端里：

```json
{
  "mcpServers": {
    "patentmax": {
      "url": "https://api.ip930.com/api/mcp",
      "headers": { "Authorization": "Bearer <你的密钥>" }
    }
  }
}
```

Claude、Cursor、扣子、以及任何支持 Model Context Protocol 的客户端都能接。

有些客户端只给你一个地址输入框，填不了请求头，那就把密钥挂在 URL 上：

```
https://api.ip930.com/api/mcp?apikey=<你的密钥>
```

**也支持 OAuth 2.1 一键授权。** 客户端顺着 401 响应里的 `resource_metadata` 自己走发现流程，你点一下确认就行，不用手动复制密钥。行业里四成公开 MCP 服务器压根没做鉴权，这块我们是认真做的。

详细步骤见 [INSTALL.md](INSTALL.md)。

## 四条常用路径

**关键词找专利** — `patent_search` 拿一批 → 挑出相关的 → `patent_brief` 逐篇细看。

别只搜一个词。技术主题拆成「对象 + 手段 + 效果」三个面，各准备几个同义词，先宽后窄跑两三轮。

**一个想法要查新** — `patent_search` 拿候选 → `similar_patents` 语义比对 → `patent_brief` 看权利要求。

关键在最后一步：**判断新颖性看的是权利要求，不是摘要。** 摘要读着像，不等于落进了保护范围，得把技术特征逐条比。

**吃透一件专利** — `patent_brief` 看权要和法律状态 → `patent_citation` 看前后引证 → `similar_patents` 看近邻。

法律状态一定要看。授权、驳回、撤回、届满、无效，意义完全不同——已经失效的专利不构成侵权障碍，但它仍然是有效的现有技术。

**摸一个领域或一家公司的底** — `tech_landscape` 的 `mode="field"` 按检索式统计领域，`mode="company"` 出企业画像。

`dimension` 可选申请人、申请年份、IPC 分类、国家、法律状态等十几个维度，换着看能得出完全不同的结论。

## 它不做什么

**不出具有法律效力的文件。** 正式查新报告、FTO 意见书、无效检索报告这类东西需要代理人签字，这个 Skill 只做检索和分析。

**法律状态是快照，不是登记簿。** 涉及侵权、无效、许可这类有法律后果的判断，以各国专利局官方登记簿为准。

**「没搜到」不等于「没有」。** 专利从申请到公开有 18 个月左右的窗口期，这段时间的申请谁也检索不到。给查新结论时要把这一点讲明白。

**申请人名称没做集团归一化。** 同一家企业可能以中文名、英文名、子公司名分散在榜单不同位置，查跨国集团时分别查各主体再合并，否则会严重低估它的专利量。
